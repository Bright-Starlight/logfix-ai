## 核心原则（Agent 必读）

### I. 规范驱动开发

每个功能都从完整的规格说明开始。功能规格必须包含可独立测试的用户场景。规格必须在编码前获得批准。

**Agent 行为要求**：在 `/speckit.spec` 批准前不得开始实现。

### II. TDD（测试驱动开发）（不可妥协）

先写测试，测试必须初始失败，实现后测试通过。必须严格遵循 Red-Green-Refactor 循环。

**Agent 行为要求**：
- 测试文件先于实现文件创建
- 测试初始必须 FAIL，方可开始实现
- 实现后测试必须 PASS，方可提交

### III. 增量交付

每个用户故事必须可独立测试和部署。MVP 优先。

**Agent 行为要求**：每个用户故事完成后应能独立演示/验证。

### IV. 代码质量

函数应小（50 行以内），文件应专注（800 行以内）。优先使用不可变性；必须明确且受控地使用可变操作。

**Agent 行为要求**：
- 单个函数不超过 50 行
- 单个文件不超过 800 行
- 禁止随意删除注释

### V. 可观测性

所有重要操作必须通过结构化日志可观测。

**Agent 行为要求**：实现的功能必须包含有意义的日志输出。

### VI. 文档语言

所有文档正文必须使用中文。报告与总结语言也必须使用中文。

**Agent 行为要求**：
- 规格说明、计划文档等正文使用中文
- 完成报告、审查报告使用中文

### VII. 代码执行流程图

在实现前必须画出 Mermaid 流程图，保存到 `specs/###-feature-name/flow.md`，**所有文字使用中文**。

**Agent 行为要求**：
- `/speckit.tasks` 阶段必须生成 flow.md
- 流程图节点、状态、说明全部使用中文

### VIII. 集成验证

实现完成后必须验证功能已正确集成到主应用，**必须通过阅读代码验证**。

**Agent 行为要求**：
- 检查组件是否已导入到主应用（如 App.tsx）
- 检查组件是否正确渲染（传递正确的 props）
- 检查 Store 状态是否正确连接
- 检查用户可见功能入口是否存在
- 检查 UI 组件是否实际使用了 store 中的数据

## 安全约束

- 不得硬编码任何密钥（API 密钥、密码、令牌）
- 所有用户输入必须验证
- 遇到无效输入快速失败

## 性能约束

- 关键路径必须包含性能测试目标
- 性能目标必须在计划中定义

## Windows 环境

所有代码和脚本必须兼容 Windows 平台。

## 工作流检查点

| 阶段 | 宪法检查点 |
|------|-----------|
| spec.md | 规格批准前不得实现 |
| plan.md | 宪法检查通过后方可进入 Phase 0 研究 |
| tasks.md | TDD 流程、flow.md 生成 |
| implement | 代码层面集成验证 |
| PR | 宪法合规性审查 |

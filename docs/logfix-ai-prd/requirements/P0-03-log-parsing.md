# P0-03 日志解析

## 背景

上传的原始日志必须结构化后才能进入聚合、筛选和 AI 分析环节。

## 目标

将文本日志或 JSON 日志解析为统一结构，并保存到 SQLite。

## 范围

- 文本日志逐行解析
- JSON 日志解析
- 提取通用字段
- 解析失败保留原文
- 解析状态记录
- 数据库存储

## 统一字段

- `timestamp`
- `level`
- `service`
- `module`
- `message`
- `stack_trace`
- `trace_id`
- `raw_text`
- `parse_status`

## 不包含

- 异常聚合
- AI 分析

## 输出

- 结构化日志记录
- 解析失败统计

## 验收标准

- 能处理常见文本和 JSON 日志
- 无法完整解析的行不丢失
- 所有日志都可追溯到原始文本

## 依赖

- 日志上传功能
- SQLite 表结构

## 建议实现

- 规则解析优先，LLM 仅作为补充
- 先覆盖时间、级别、消息三个核心字段

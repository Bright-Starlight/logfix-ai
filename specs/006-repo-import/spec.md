# Feature Specification: 仓库导入功能

**Feature Branch**: `006-repo-import`  
**Created**: 2026-04-12  
**Status**: In Progress（UI 原型已完成，后端实现待开发）  
**Input**: 添加仓库导入功能；支持本地和github；完成后才进入日志上传切分结构化的相关页面

> 生成内容的正文必须使用中文；标题保留英文标签仅用于模板标准化。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导入本地仓库 (Priority: P1)

用户打开应用后，首先进入仓库导入页面。用户选择"本地仓库"方式，输入本地仓库的绝对路径，触发验证后系统确认目录为有效仓库并展示预览，用户确认后跳转至日志上传与处理页面。

**Why this priority**: 本地仓库导入是最常见的起点，也是用户能够快速上手的最低门槛路径，不依赖网络，必须优先支持。

**Independent Test**: 用户可以在不依赖网络的情况下，通过选择本地目录完成仓库导入并进入日志上传页面，可独立验证整个 P1 路径。

**Acceptance Scenarios**:

1. **Given** 用户打开应用，**When** 应用加载完成，**Then** 首页直接显示仓库导入界面，不显示其他功能页面。
2. **Given** 用户选择本地导入，**When** 用户在路径输入框中输入有效的本地仓库绝对路径并触发验证，**Then** 系统显示仓库名称与路径预览，并提供"确认导入"按钮。
3. **Given** 用户已确认本地仓库，**When** 用户点击"确认导入"，**Then** 系统完成导入流程并跳转至日志上传页面。
4. **Given** 用户选择了一个不存在或无法访问的目录，**When** 用户点击"确认导入"，**Then** 系统显示明确的错误提示，用户停留在导入页面可重试。

---

### User Story 2 - 导入 GitHub 仓库 (Priority: P2)

用户打开应用，选择"GitHub 仓库"方式，输入仓库地址（URL 或 owner/repo 格式）和本地克隆目标路径，系统验证仓库有效性后展示预览，用户确认后系统执行克隆并跳转至日志上传与处理页面。

**Why this priority**: GitHub 仓库导入扩展了用户来源，使远程协作项目也能被分析，是核心功能的重要补充。

**Independent Test**: 用户输入合法的公开 GitHub 仓库地址并指定克隆目标路径，系统完成克隆并进入日志上传页面，可独立验证此路径。

**Acceptance Scenarios**:

1. **Given** 用户选择 GitHub 导入方式，**When** 用户输入合法的公开仓库地址，**Then** 系统校验地址格式并显示仓库基本信息（名称、描述）预览。
2. **Given** 用户选择 GitHub 导入方式，**When** 用户未输入克隆目标路径，**Then** "确认导入"按钮处于禁用状态。
3. **Given** 用户已确认 GitHub 仓库信息和克隆目标路径，**When** 用户点击"确认导入"，**Then** 系统执行 git clone 并跳转至日志上传页面。
4. **Given** 用户输入了不存在或无法访问的 GitHub 仓库地址，**When** 用户触发导入，**Then** 系统显示明确错误信息（如"仓库不存在"或"无访问权限"），用户停留在导入页面。
5. **Given** 用户需要导入私有 GitHub 仓库，**When** 用户输入仓库地址，**Then** 系统提示需要配置 GitHub Token 并引导用户完成授权流程。

---

### User Story 3 - 导入完成后进入日志处理流程 (Priority: P3)

用户完成仓库导入（本地或 GitHub）后，系统自动跳转至日志上传、切分和结构化页面，开始日志分析工作。未完成导入的用户无法访问日志处理页面。

**Why this priority**: 仓库导入是前置步骤，导入完成后必须无缝衔接日志处理流程，且需要页面守卫防止跳过导入步骤。

**Independent Test**: 任意方式完成导入后，验证系统正确跳转至日志上传页面，且未导入时直接访问日志处理页面会被重定向至导入页面。

**Acceptance Scenarios**:

1. **Given** 仓库导入成功，**When** 系统完成导入操作，**Then** 自动跳转至日志上传页面，无需用户额外操作。
2. **Given** 用户未完成仓库导入，**When** 用户尝试直接访问日志上传页面，**Then** 系统重定向用户至仓库导入页面，并提示"请先导入仓库"。
3. **Given** 用户在日志处理页面，**When** 用户选择切换仓库，**Then** 系统返回仓库导入页面，允许重新选择或导入新仓库。

---

### Edge Cases

- 用户选择的本地目录不是有效的 Git 仓库（无 `.git` 目录）时如何处理？→ 提示"所选目录不是有效的 Git 仓库"，不执行导入。
- 用户选择的本地目录权限受限，应用无法读取时如何处理？→ 提示"无法读取该目录，请检查访问权限"。
- GitHub 仓库地址格式多样（HTTPS URL、owner/repo 简写），如何统一处理？→ 系统支持主流格式，自动标准化。
- 网络连接中断时，GitHub 仓库导入失败如何告知用户？→ 显示网络错误提示，保留用户已输入内容，允许重试。
- 用户在导入过程中关闭应用，下次打开是否保留上次状态？→ 初版不恢复中断状态，重新显示导入页面。
- 同一仓库被重复导入时如何处理？→ 系统允许重复导入，替换当前会话中的仓库上下文。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 应用启动后，系统必须将仓库导入页面作为首页展示，用户在导入仓库之前无法访问其他功能页面。
- **FR-002**: 系统必须支持用户通过路径输入的方式指定本地仓库目录（输入绝对路径后触发验证），不要求提供操作系统原生文件选择对话框。
- **FR-003**: 系统必须校验用户选择的本地目录是否为有效 Git 仓库（包含 `.git` 目录），无效时显示明确错误提示。
- **FR-004**: 系统必须支持用户输入 GitHub 仓库地址（支持 HTTPS URL 及 owner/repo 简写格式），并完成仓库信息预览。
- **FR-004.1**: 系统必须在 GitHub 仓库导入时，要求用户指定本地克隆目标路径，且必须为绝对路径格式。
- **FR-005**: 导入流程分为两步：①「验证」——系统检查输入有效性并展示仓库名称与路径预览；②「确认导入」——用户主动点击后才正式完成导入并跳转下一步。验证通过前确认按钮不可用。
- **FR-006**: 系统必须在 GitHub 仓库导入时，检测仓库是否为私有仓库，私有仓库需引导用户完成 GitHub 身份验证后继续。
- **FR-007**: 系统必须在仓库导入成功后，自动跳转至日志上传与处理页面。
- **FR-008**: 系统必须在用户未导入仓库时，阻止访问日志上传与处理页面，并重定向至导入页面，附带提示语。
- **FR-009**: 系统必须在导入失败时，向用户展示可理解的错误信息，并允许用户修改输入后重试。
- **FR-010**: 用户在日志处理页面必须能够返回仓库导入页面，以替换当前仓库并重新开始分析流程。

### Observability & Diagnostics *(mandatory if feature changes runtime behavior)*

- **OBS-001**: 每次仓库导入操作（成功或失败）必须记录日志，包含：导入类型（本地/GitHub）、时间戳、操作结果（成功/失败）。
- **OBS-002**: 导入失败时，日志级别为 ERROR，必须包含失败原因（错误类型、错误消息）；导入成功时，日志级别为 INFO，包含仓库路径或远程地址、仓库名称。
- **OBS-003**: 日志文件输出至 `/log` 目录，命名格式为 `logfix-ai_{日期}.log`，例如 `logfix-ai_20260412.log`，按日轮转。

### Key Entities *(include if feature involves data)*

- **Repository（仓库）**: 表示用户导入的代码仓库，关键属性：来源类型（本地/GitHub）、路径或远程地址、仓库名称、导入时间、导入状态。
- **ImportSession（导入会话）**: 表示一次导入操作的上下文，包含操作类型、发起时间、结果状态、错误信息（失败时）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开应用到完成本地仓库导入并进入日志页面，整个操作流程可在 30 秒内完成（不含文件系统浏览时间）。
- **SC-002**: 用户从输入公开 GitHub 仓库地址到完成导入并进入日志页面，可在 60 秒内完成（含网络请求时间，正常网络环境下）。
- **SC-003**: 90% 的首次使用用户能够独立完成仓库导入，无需查阅帮助文档。
- **SC-004**: 所有导入失败场景均有明确错误提示，用户可根据提示自行修正输入并完成重试，无需重启应用。
- **SC-005**: 每次仓库导入操作（成功与失败）均可通过日志文件追踪到完整的操作输入与结果，支持事后排查。

## Assumptions

- GitHub 私有仓库需要用户配置 `GITHUB_TOKEN` 环境变量；无 Token 时无法导入私有仓库。
- 应用运行在用户本地机器上，可直接访问本地文件系统，无需额外权限申请流程。
- 用户已在本地安装 Git 客户端（系统需调用 `git clone` 命令）。
- 日志上传与处理功能已作为现有功能存在，本特性仅负责前置的仓库导入流程与页面守卫逻辑，不修改现有日志处理逻辑。
- 不需要在仓库导入阶段分析仓库内容，仅需确认仓库有效性并记录元数据。
- 初版不提供仓库导入历史记录或收藏功能，每次使用均需重新导入。
- 不需要支持非 Git 仓库（如 SVN、Mercurial 等）。
- GitHub 克隆目标路径由用户显式指定，系统不做自动推导或默认填充。

## Design Decisions *(UI 原型已确定)*

> 本节记录 UI 原型阶段已敲定的 UX 决策，作为后续开发的约束基准。

### 全局布局：五步流水线侧边栏

应用采用固定左侧边栏导航，展示完整的五步分析流水线：

```
① 仓库导入  ←（本特性，首页守卫）
② 日志上传
③ 日志切分
④ 日志分类
⑤ 分析结果
```

- 每个步骤以节点 + 连接线形式呈现，直观显示进度。
- 已完成的步骤可点击回溯；未到达的步骤不可点击（置灰）。
- 用户可随时通过「重置流程」按钮回到步骤①。

### 仓库导入页 UX 决策

| 决策点 | 已确定方案 |
|--------|-----------|
| 入口方式 | 顶部方法切换 Tab（本地 / GitHub），默认选中「本地仓库」 |
| 本地路径选择 | 支持两种方式：① 点击按钮弹出 Windows 资源管理器选择文件夹；② 用户也可直接输入绝对路径后触发验证 |
| GitHub 地址输入 | 文本框，支持 `owner/repo` 简写与完整 HTTPS URL，自动标准化 |
| GitHub 克隆路径 | 点击按钮弹出 Windows 资源管理器，选择目标文件夹后自动填充路径 |
| 验证流程 | 验证通过后展示仓库预览卡（名称 + 路径 + 来源类型徽章），卡片内提供「确认导入」按钮 |
| 错误反馈 | 行内错误信息（输入框红色边框 + 文字说明），不弹模态框 |
| 切换方法 | 切换 Tab 时清除已有预览和错误，不保留前一方法的输入内容 |

### 应用守卫实现方式

页面守卫通过应用状态机实现（非 URL 路由层面），每个步骤只有在前置步骤完成后才会解锁。当前选中步骤之前的步骤均可回溯点击，之后的步骤保持不可用。

# Feature Specification: 日志文件切分

**Feature Branch**: `001-log-split`
**Created**: 2026-04-10
**Status**: Draft
**Input**: 用户描述: "生产日志分析系统，web页面，第一版的功能是输入日志文件，将日志文件进行切分；切分规则有多种类型，常见的如正则表达式"

> 生成内容的正文必须使用中文；标题保留英文标签仅用于模板标准化。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 日志文件上传与预览 (Priority: P1)

用户需要将本地日志文件上传到系统，并在界面上预览文件内容，以便确认文件正确上传。

**Why this priority**: 文件上传是所有后续操作的基础，没有文件就无法进行任何切分操作。

**Independent Test**: 可以通过模拟文件上传并验证系统返回文件内容来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户打开系统首页， **When** 用户选择并上传一个文本日志文件， **Then** 系统显示上传成功并预览文件内容前100行
2. **Given** 用户上传了非文本文件， **Then** 系统显示错误提示"仅支持文本文件"
3. **Given** 用户未选择任何文件就点击上传， **Then** 系统显示提示"请选择文件"

---

### User Story 2 - 正则表达式切分规则 (Priority: P1)

用户需要使用正则表达式作为切分规则，将日志文件按行匹配模式进行切分，提取出有意义的日志条目。

**Why this priority**: 正则是最常用的日志切分方式，是MVP的核心功能。

**Independent Test**: 可以通过上传已知内容的日志文件，应用正则规则，验证切分结果是否正确提取了匹配的日志条目。

**Acceptance Scenarios**:

1. **Given** 用户已上传日志文件， **When** 用户输入正则表达式 `^\d{4}-\d{2}-\d{2}` 匹配日期开头行， **Then** 系统将日志按日期行切分成多个段落
2. **Given** 用户输入了无效的正则表达式， **Then** 系统显示错误提示"正则表达式无效"并高亮输入框
3. **Given** 日志内容没有匹配正则的行， **Then** 系统显示"未找到匹配项"
4. **Given** 用户应用正则切分后， **When** 用户修改正则表达式， **Then** 系统重新计算切分结果

---

### User Story 3 - 固定分隔符切分规则 (Priority: P2)

用户需要使用固定字符串（如空行、特定标记）作为分隔符来切分日志文件。

**Why this priority**: 固定分隔符是仅次于正则的常用方式，可以覆盖更多日志格式。

**Independent Test**: 可以通过上传已知内容的日志，设置分隔符，验证切分结果。

**Acceptance Scenarios**:

1. **Given** 用户已上传日志文件， **When** 用户选择"空行分隔"并应用， **Then** 系统将日志按连续空行切分成多个段落
2. **Given** 用户选择"自定义分隔符"并输入 `---`， **Then** 系统按 `---` 出现位置切分日志
3. **Given** 分隔符在文件中未出现， **Then** 系统显示"未找到分隔符"

---

### User Story 4 - 切分结果查看与复制 (Priority: P1)

用户需要查看切分后的结果，并能复制切分后的内容。

**Why this priority**: 切分是为了得到可用的日志片段，方便后续分析和处理。

**Independent Test**: 可以通过执行切分后验证结果展示和复制功能。

**Acceptance Scenarios**:

1. **Given** 用户已执行切分， **When** 用户点击某个切分片段， **Then** 该片段高亮显示并展示完整内容
2. **Given** 用户已选择切分片段， **When** 用户点击"复制"按钮， **Then** 片段内容被复制到剪贴板并显示"已复制"提示
3. **Given** 用户已执行切分， **When** 用户展开所有片段， **Then** 系统显示每个片段的序号和行数统计

---

### Edge Cases

- 用户上传超大文件（超过100MB）：**分片上传，后端Python流式处理，前端仅传输文件**
- 日志文件编码不是UTF-8：**检测编码，若检测失败则提示用户手动确认文件编码**
- 正则表达式匹配结果过多（超过10000个片段）：**分页展示，每页最多显示1000个片段**
- 用户在切分过程中刷新页面：**后端保存切分进度与状态，刷新后前端查询状态并继续（支持断点续查）**

### Integration Requirements

#### 异步操作与状态管理

- **IR-001**: 前端必须每2秒轮询一次 `GET /api/sessions/{session_id}` 获取切分进度，直到状态变为 `completed` 或 `failed`
- **IR-002**: 切分操作必须设置超时机制，单次切分任务超时时间为300秒（5分钟），超时后状态标记为 `failed`
- **IR-003**: 用户可以在切分进行中查看已完成的片段（部分结果获取），系统返回当前可用的结果
- **IR-004**: 切分任务一旦启动不可取消，用户需等待完成或刷新页面重新开始
- **IR-005**: 切分中途失败时，系统记录错误状态和错误信息，用户可查看失败原因但不可重试

#### 会话生命周期

- **IR-006**: 会话创建后24小时内可查询，逾期自动清理
- **IR-007**: 用户刷新页面后，前端必须自动查询最近一次切分会话的状态并重建UI状态
- **IR-008**: 同一文件在同一时间只能有一个进行中的切分会话（`SPLIT_IN_PROGRESS` 冲突检测）

#### 操作前验证

- **IR-009**: 固定字符串分隔符必须校验非空，分隔符长度不超过100字符
- **IR-010**: 文件上传后、切分执行前，系统必须验证文件完整性（文件存在且可读）

#### 边界错误处理

- **IR-011**: 文件上传成功后、开始切分前文件被删除：**返回 `FILE_NOT_FOUND` 错误，引导用户重新上传**
- **IR-012**: 切分完成后、会话过期前结果被删除：**返回 `SESSION_NOT_FOUND` 错误，提示会话已过期**
- **IR-013**: 网络请求必须实现重试机制，失败后自动重试最多3次，间隔1秒、2秒、4秒指数退避
- **IR-014**: 文件预览行数统计必须与实际切分使用的行数一致，确保展示与切分数据同源

#### 数据一致性

- **IR-015**: 同一文件重复上传生成新的 `file_id`，旧文件保留（不做覆盖）
- **IR-016**: 上传时检测的编码必须与结果存储使用的编码一致，切分时不再重新检测
- **IR-017**: 列表视图和详情视图的片段内容必须一致，不允许数据不一致

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许用户上传本地文本日志文件（.log, .txt, .json 等常见格式）
- **FR-001b**: 系统必须支持分片上传大文件（超过100MB），后端流式处理
- **FR-002**: 系统必须在文件上传后显示文件内容预览（默认前100行）
- **FR-003**: 系统必须支持正则表达式作为切分规则
- **FR-004**: 系统必须支持固定分隔符切分（空行、自定义字符串）
- **FR-005**: 系统必须在用户输入正则表达式时进行实时语法校验
- **FR-006**: 系统必须在切分完成后展示切分结果列表（大量结果时分页展示，每页最多1000个片段）
- **FR-007**: 系统必须允许用户点击查看每个切分片段的完整内容
- **FR-008**: 系统必须允许用户复制切分片段内容到剪贴板
- **FR-009**: 系统必须在切分过程中显示进度指示器
- **FR-010**: 系统必须在操作完成后记录结构化日志到 `/log` 目录
- **FR-011**: 系统必须自动检测文件编码（UTF-8为主），若检测失败则提示用户确认
- **FR-012**: 第一版为本地单用户工具，无需用户认证
- **FR-013**: 系统必须支持切分状态追踪（待处理/处理中/已完成），刷新后可查询并继续
- **FR-014**: 切分结果必须持久化到PostgreSQL数据库，支持会话内随时查看

### Observability & Diagnostics *(mandatory if feature changes runtime behavior)*

- **OBS-001**: 必须记录文件上传事件，包含文件名、文件大小、上传时间
- **OBS-002**: 必须记录切分规则应用事件，包含规则类型、规则内容、匹配数量
- **OBS-003**: 必须记录错误事件，包含错误类型、错误消息、操作上下文
- **OBS-004**: 日志文件命名规范为 `logfix-ai_{日期}.log`，例如 `logfix-ai_20260410.log`
- **OBS-005**: 日志必须包含时间戳、日志级别、事件名称、关键数据字段

### Key Entities *(include if feature involves data)*

- **LogFile**: 上传的日志文件，包含文件名、文件大小、编码、原始内容、存储路径
- **SplitRule**: 切分规则，包含规则类型（regex/fixed-string）、规则内容、规则名称
- **SplitResult**: 切分结果，包含片段序号、起始行号、结束行号、片段内容、匹配次数
- **SplitSession**: 切分会话（PostgreSQL），关联LogFile与多个SplitResult，包含会话ID、状态、创建时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在60秒内完成从打开页面到查看切分结果的全流程
- **SC-002**: 系统可以处理100MB以内的日志文件
- **SC-003**: 正则表达式校验响应时间小于200毫秒
- **SC-004**: 切分10000行日志的时间不超过5秒
- **SC-005**: 切分结果准确性达到100%（每个匹配片段正确提取）
- **SC-006**: 所有关键操作都记录到日志文件，可追溯操作历史

## Assumptions

- 用户上传的日志文件编码为 UTF-8
- 第一版 MVP 聚焦于日志切分核心功能，不包含日志解析、元数据提取等高级功能
- 单个切分片段内容不超过1MB（展示和复制时）
- 用户熟悉基本的正则表达式语法
- 系统运行在 Windows 环境，文件路径使用反斜杠
- **后端采用 Python 实现**
- **前端采用 React**
- **前端采用分片上传，后端流式处理大文件**
- **数据库采用 PostgreSQL 存储切分结果**
